# christina-hurghada.photos: сайт фотографа

Одностраничный сайт фотографа Кристины Селезнёвой (Хургада, Египет), статический, GitHub Pages из ветки `main`
(репозиторий `selesnow/photos`). Владелец: Алексей (муж Кристины). Тексты сайта и общение: русский.

## Жёсткие ограничения владельца (не нарушать)

- **Анимации и визуальные эффекты не трогать** (reveal в hero, canvas-частицы, blur-орбы): без них, по мнению владельца,
  сайт выглядит дёшево.
- **Никакого Яндекса** (Вебмастер, Метрика, Карты): владельцы из Украины. Российские сервисы тоже лучше не предлагать.
- **Видимые тексты не менять** (H1, описания): владельцу нравится текущая формулировка. Цены в тексте обновляются
  автоматически из `prices.json`, это не правка копирайта.
- **Файлы фото не переименовывать, alt не менять**, существующие слайды не переставлять и не удалять.
- **Один лендинг:** без многостраничности, блога и других языков (Кристина говорит только по-русски/по-украински).
- Допустимы невидимые технические улучшения и офф-пейдж через Google/международные площадки.

### Управление сайтом через Telegram-бота (@photosessions_chat_bot, личка, только админы)

- **Фото:** отправить боту фото → выбрать категорию и локацию → «Опубликовать» → Action `photos.yml` скачивает фото,
  делает WebP и миниатюры через `add_photos.py --drop-originals` (оригиналы в репозиторий не попадают), вставляет слайды
  в начало раздела и в `sitemap.xml`, коммитит в `main`, бот пишет «✅ Добавлено».
- **Цены:** `/prices` → раздел → позиция → ± или ввод числа → «Опубликовать» → Action `prices.yml` → `update_prices.py`
  меняет `prices.json` и `apply_prices.py` переписывает цены в `index.html`.
- **Чат на сайте:** виджет → Worker → группа «Фотосессии» в Telegram, ответ Reply возвращается в виджет.

Из-за этого **`main` пополняется коммитами от `github-actions[bot]`** («Фото через Telegram…», «Цены через Telegram…»).
Перед работой и перед push всегда `git pull --rebase origin main`.

## Правила работы

- **Цены руками не править** ни в `index.html`, ни в `script.js`: менять `prices.json` и запускать
  `python .github/scripts/apply_prices.py`; проверка: `--check`, тесты: `python -I .github/scripts/test_prices.py`.
  Если правило в `apply_prices.py` не находит фрагмент (поменяли вёрстку), скрипт падает с ошибкой, это нормально:
  поправить правило, а не обходить.
- **Новые фото** локально: навык `add-photos`. Не коммитить, пока владелец не попросил.
- **Калькулятор** берёт числа из `data-price`, `data-transfer`, `data-dress-free` в `index.html`, не из JS. Правило
  платья: в «Летящее платье» входит одно платье только на локациях из `types.dress.dress_included_at` (сейчас только
  «Пустыня»; «Море + Пустыня» платное), на остальных калькулятор сам добавляет аренду платья. Меняя калькулятор,
  сравнивайте результат со снимком всех комбинаций (тип × локация × опции) до и после.
- Изменения, видимые посетителям или меняющие боевой Worker/секреты/GitHub-токены, **согласовывать с владельцем до
  публикации**. Деплой Worker: порядок и подводные камни в `..\tg-chat-worker\README.md`.
- **Секреты никогда не печатать и не коммитить**: токен бота (переменная среды `PHOTOSESSION_CHAT_BOT`), GitHub-токен
  (`GITHUB_TOKEN_PHOTOS`), секреты Worker. Передавать через stdin или переменные окружения, не аргументами и не в чат.
- Репозиторий публичный, и **Pages публикует всё его содержимое**: любой новый файл будет доступен на сайте. Код Worker
  и всё, что не должно быть открыто, держать вне этого репозитория.

## Ловушки на этой машине (Windows)

- Python: `Path.read_text(newline=...)` есть только с 3.13, используйте `open(..., newline="")`. Вывод кириллицы в консоль
  падает с `UnicodeEncodeError` (cp1251): `sys.stdout.reconfigure(encoding="utf-8")`. Для скриптов репозитория запускать
  `python -I`.
- Файлы сайта могут быть с CRLF: при правке сохранять исходные окончания строк (`apply_prices.py` и `add_photos.py` это делают).
- Правки через `python - <<EOF` в Bash: обратные слэши (`\n`, `\\`) в тексте могут исказиться по пути. Для замен со строками,
  содержащими `\n`, надёжнее инструмент Edit или `chr(92)`; после правки JS-файлов проверять сборку, а не только `node --check`.
- Фоновые процессы `wrangler dev`/`workerd` остаются после прерванных тестов и блокируют `.wrangler/state`: остановить.
- Pages после коммита от бота собирается ~1 минуту, плюс кэш браузера.
