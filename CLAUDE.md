# christina-hurghada.photos: сайт фотографа

Одностраничный сайт фотографа Кристины Селезнёвой (Хургада, Египет), статический, GitHub Pages из ветки `main`
(репозиторий `selesnow/photos`). Владелец: Алексей (муж Кристины). Тексты сайта и общение: русский.

## Жёсткие ограничения владельца (не нарушать)

- **Анимации и визуальные эффекты не трогать** (reveal в hero, canvas-частицы, blur-орбы): без них, по мнению владельца,
  сайт выглядит дёшево.
- **Никакого Яндекса** (Вебмастер, Метрика, Карты): владельцы из Украины. Российские сервисы тоже лучше не предлагать.
- **Видимые тексты не менять** (H1, описания): владельцу нравится текущая формулировка. Цены в тексте обновляются
  автоматически из `prices.json`, это не правка копирайта.
- **Файлы фото не переименовывать, alt не менять**, существующие слайды не переставлять и не удалять.
- **Один лендинг:** без многостраничности, блога и других языков (Кристина говорит только по-русски/по-украински).
- Допустимы невидимые технические улучшения и офф-пейдж через Google/международные площадки.

### Управление сайтом через Telegram-бота (@photosessions_chat_bot, личка, только админы)

- **Фото:** отправить боту фото → выбрать категорию и локацию → «Опубликовать» → Action `photos.yml` скачивает фото,
  делает WebP и миниатюры через `add_photos.py --drop-originals` (оригиналы в репозиторий не попадают), вставляет слайды
  в начало раздела и в `sitemap.xml`, коммитит в `main`, бот пишет «✅ Добавлено».
- **Цены:** `/prices` → раздел → позиция → ± или ввод числа → «Опубликовать» → Action `prices.yml` → `update_prices.py`
  меняет `prices.json` и `apply_prices.py` переписывает цены в `index.html`.
- **Чат на сайте:** виджет → Worker → группа «Фотосессии» в Telegram, ответ Reply возвращается в виджет.

Из-за этого **`main` пополняется коммитами от `github-actions[bot]`** («Фото через Telegram…», «Цены через Telegram…»).
Перед работой и перед push всегда `git pull --rebase origin main`.

## Правила работы

- **Цены руками не править** ни в `index.html`, ни в `script.js`: менять `prices.json` и запускать
  `python .github/scripts/apply_prices.py`; проверка: `--check`, тесты: `python -I .github/scripts/test_prices.py`.
  Скрипт ищет места **по идентификаторам** (`data-p`, `data-type`, `data-loc`, `data-extra`, `sku`), не по тексту;
  если идентификатора нет или он не совпадает с `prices.json`, он падает с понятной ошибкой: это нормально, чинить
  разметку или `prices.json`, а не обходить. Схема и порядок действий: [PRICES.md](PRICES.md).
- **Новые фото** локально: навык `add-photos`. Не коммитить, пока владелец не попросил.
- **Калькулятор** (`script.js`) не содержит ни цен, ни названий: числа берёт из `data-price`, `data-transfer`,
  `data-dress-free`, `value` в `index.html`, подписи из `data-label`/`data-clean`. Правило платья: в «Летящее платье»
  входит одно платье только на локациях из `types.dress.dress_included_at` (сейчас только «Пустыня»; «Море + Пустыня»
  платное), на остальных калькулятор сам добавляет аренду платья. Меняя калькулятор, запускайте
  `node .github/tests/calc.test.mjs`: он проверяет итог для **всех** комбинаций (тип × локация × опции) по `prices.json`.
- **Новую локацию, тип съёмки или доп. услугу добавлять данными, не кодом:** запись в `prices.json` + разметка по
  образцу соседних (подробно в [PRICES.md](PRICES.md) и навыке `update-prices`). После этого `check_site.py` сам
  перечислит, чего не хватает на странице. Деплой Worker для этого не нужен: бот берёт локации и цены из `prices.json`.
- Изменения, видимые посетителям или меняющие боевой Worker/секреты/GitHub-токены, **согласовывать с владельцем до
  публикации**. Деплой Worker: порядок и подводные камни в `..\tg-chat-worker\README.md`.
- **Секреты никогда не печатать и не коммитить**: токен бота (переменная среды `PHOTOSESSION_CHAT_BOT`), GitHub-токен
  (`GITHUB_TOKEN_PHOTOS`), секреты Worker. Передавать через stdin или переменные окружения, не аргументами и не в чат.
  Секреты живут **только вне git**: в Cloudflare (`BOT_TOKEN`, `GITHUB_TOKEN`, `WEBHOOK_SECRET`), в GitHub Secrets сайта
  (`TELEGRAM_BOT_TOKEN`) и в переменных среды на машине владельца. Значение `WEBHOOK_SECRET` нигде не сохранено. При
  восстановлении окружения с нуля (новый компьютер, перевыпуск токена) секреты задаются заново, порядок в README Worker.
- Код Worker после каждой правки коммитить и пушить в приватный `selesnow/tg-chat-worker`: боевой Worker в Cloudflare
  и репозиторий должны совпадать, иначе откат и восстановление опираются на устаревший код.
- Репозиторий публичный, и **Pages публикует всё его содержимое**: любой новый файл будет доступен на сайте. Код Worker
  и всё, что не должно быть открыто, держать вне этого репозитория.

## Что нельзя ломать при правке сайта (автоматизации опираются на вёрстку)

Бот и Action'ы вставляют фото и цены в `index.html` по конкретным якорям. После **любой** правки `index.html`,
`script.js`, `sitemap.xml`, FAQ или названий запустите `python -I .github/scripts/check_site.py` (то же делает Action
`check.yml` на каждый push в `main`): он скажет, что именно сломано и что чинить.

- **Портфолио:** вкладки `id="tab-family|couple|single"` → `<div class="swiper swiper-…">` → `<div class="swiper-wrapper">` и
  **перевод строки сразу после него**. Туда `add_photos.py` вставляет новые фото; не переименовывать id/классы, не
  склеивать строки. Шаблон слайда не менять: `add_photos.py` создаёт слайды по нему.
- **Локации:** ключи (`hurghada`, `el_gouna`…) одинаковы в `prices.json`, `data-loc` кнопок калькулятора и карточек
  локаций. Название на фото портфолио (`data-location`) должно совпадать **дословно** с `photo_name` в `prices.json`
  (`Утес` ≠ `Утёс`), его проверяет `add_photos.py`; бот берёт список локаций, `photo_name` и `aliases` для разбора
  подписей из `prices.json`. Переименовывая локацию, меняйте `photo_name` и `data-location` у уже добавленных фото вместе.
- **Цены и тексты:** тексты страницы можно править свободно, пока остаются метки (`data-p`, `data-p-list`, `data-type`,
  `data-loc`, `data-extra`, `"sku"` в Schema). Нельзя удалять метку вместе с текстом: правила считают, что метка есть у
  каждой позиции из `prices.json` (`check_site.py` назовёт, чего нет). Исключения, где ищется текст: «от $N» в
  title/og/twitter (`фотосессии от $…`) и `priceRange`. Ответы FAQ в Schema выводятся из видимого FAQ автоматически.
- **`sitemap.xml`:** формат строк `<image:image><image:loc>…/img/<раздел>/N.webp…` и `<lastmod>`: на них опирается вставка.
- **Файлы фото:** нумерация сквозная (`N.webp`), следующий номер = максимальный + 1; в папках портфолио не оставлять
  файлов с нечисловыми именами (их примут за новые фото).
- **Чат:** `chat.css`/`chat.js` подключены в `index.html`; адрес Worker зашит в `chat.js`; домен сайта прописан в
  `ALLOWED_ORIGINS` Worker (смена домена = обновить Worker, иначе чат перестанет отправлять сообщения).
- **Аналитика:** события и параметры GA4 описаны в `ANALYTICS.md`; переименование события ломает отчёты, новый параметр
  нужно зарегистрировать (`setup_ga4.R`).
- **Репозиторий и ветка:** ветка называется `main` (на ней завязаны Action'ы и чтение `prices.json` ботом), репозиторий
  `selesnow/photos` (его имя в `GITHUB_REPO` Worker и в токене). Переименование = обновить Worker и токен.
- Файлы `.github/workflows/*` и `.github/scripts/*` — часть автоматизаций, правка только осознанная и с проверкой.

## Ловушки на этой машине (Windows)

- Python: `Path.read_text(newline=...)` есть только с 3.13, используйте `open(..., newline="")`. Вывод кириллицы в консоль
  падает с `UnicodeEncodeError` (cp1251): `sys.stdout.reconfigure(encoding="utf-8")`. Для скриптов репозитория запускать
  `python -I`.
- Файлы сайта могут быть с CRLF: при правке сохранять исходные окончания строк (`apply_prices.py` и `add_photos.py` это делают).
- Правки через `python - <<EOF` в Bash: обратные слэши (`\n`, `\\`) в тексте могут исказиться по пути. Для замен со строками,
  содержащими `\n`, надёжнее инструмент Edit или `chr(92)`; после правки JS-файлов проверять сборку, а не только `node --check`.
- Фоновые процессы `wrangler dev`/`workerd` остаются после прерванных тестов и блокируют `.wrangler/state`: остановить.
- Pages после коммита от бота собирается ~1 минуту, плюс кэш браузера.

## Навыки проекта (`.claude/skills`)

- `add-photos`: добавление новых фото из папок в портфолио;
