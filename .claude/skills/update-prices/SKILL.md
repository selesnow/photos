# Цены на сайте

Единственный источник цен — `prices.json`. Все места на сайте (карточки, калькулятор, Schema.org, title, FAQ)
генерирует `.github/scripts/apply_prices.py`. **Цены в `index.html` и `script.js` руками не правим.**
Подробности и схема: [PRICES.md](../../../PRICES.md).

Владелец и Кристина обычно меняют цены сами через бота (`/prices` в личке). Ассистента зовут, когда нужно
изменить **структуру или правила**, а не просто число.

## Обычное изменение числа

1. `git pull --rebase origin main`: бот коммитит цены в `main`, не работайте поверх устаревшей копии.
2. Отредактировать значение в `prices.json` (целое число; цена съёмки ≥ 1, остальное ≥ 0).
3. `python .github/scripts/apply_prices.py`: перепишет `index.html`.
4. `python -I .github/scripts/test_prices.py` и `python .github/scripts/apply_prices.py --check`: оба без ошибок.
5. `git diff`: должны измениться только `prices.json` и `index.html`, и только цифры/атрибуты. Коммитить и пушить —
   по просьбе владельца (изменение видно посетителям).

## Структурные изменения (новый тип, локация, услуга; новое правило)

Это правка нескольких мест сразу, делайте по порядку:

1. **`prices.json`**: добавить позицию (`types` / `locations` / `extras`; у локации `surcharge` и `transfer`,
   у типа `price`, опционально `dress_included_at`). Ключи типов и локаций совпадают с `data-type` / `data-loc`
   в калькуляторе.
2. **`index.html`**: добавить кнопку/чекбокс/карточку в той же вёрстке, что соседние. Видимые тексты согласовать с
   владельцем (он не любит, когда меняют формулировки).
3. **`apply_prices.py`**: правила замены жёстко проверяют, сколько раз сработали («ожидалось N»): обновить ожидаемые
   числа и при необходимости сам шаблон. Новое место с ценой = новое правило.
4. **`script.js`**: названия новых позиций в `typeLabels` / `locLabels` (числа берутся из data-атрибутов сами).
5. **Бот** подхватит позицию автоматически: он строит меню по `prices.json`. Если появилось новое поле, которое
   можно менять, добавить его в `FIELDS` в `..\tg-chat-worker\src\prices.js` и в `update_prices.py`
   (разрешённые поля), затем деплой Worker (навык `chat-worker`).
6. **Калькулятор нужно проверять числами**: снять итог и текст сообщения для всех комбинаций тип × локация × опции
   до и после правки (Playwright, все `#calc-type-grid` × `#calc-loc-grid` × 4 чекбокса) и убедиться, что расходятся
   только ожидаемые случаи.

## Правила, которые легко сломать

- Итог = тип + доплата локации + трансфер (если выбран) + доп. услуги. Эль-Гуна добавляет доплату к любому типу.
- «Летящее платье»: одно платье входит только на локациях из `dress_included_at` (сейчас «Пустыня», «Море + Пустыня» платное);
  на остальных калькулятор автоматически добавляет `extras.dress.price`. Чекбокс «доп. платье» всегда платный.
- `priceRange` в Schema = от минимальной цены съёмки до (максимальная съёмка + максимальная доплата + максимальный трансфер).
- В FAQ цены встречаются дважды (HTML и Schema JSON-LD): правила `apply_prices.py` обновляют обе копии.
