# Добавление новых фото в портфолио

Разделы портфолио и папки: `family` — Семейные, `couple` — Парные, `single` — Индивидуальные.
Новые фото узнаются по нечисловому имени (например `photo_2026-10-24_21-05-01.jpg`):
все опубликованные фото уже переименованы в `1.jpg`, `2.jpg`, …

> Основной способ добавлять фото теперь — **через Telegram-бота** (личка, кнопки категории и локации,
> «Опубликовать»): Action `photos.yml` вызывает тот же `add_photos.py` с флагом `--drop-originals` (оригиналы в
> репозиторий не попадают). Этот навык — для фото, которые лежат в папках сайта локально. Бот коммитит в `main`,
> поэтому перед работой `git pull --rebase origin main`, иначе номера фото разойдутся.

Всю механику делает `scripts/add_photos.py` — используй его, а не правь index.html вручную:
так вёрстка слайда, alt, миниатюры и sitemap каждый раз получаются одинаковыми.

## Шаги

1. **Найти новые фото**
   `python .claude/skills/add-photos/scripts/add_photos.py find`
   Покажет новые файлы по разделам и точные названия локаций, которые уже есть на сайте.
   Если новых фото нет, но пользователь уверен, что добавил, — проверь `git status`:
   возможно, они лежат не в той папке (например, прямо в `img/`) — спроси, в какой раздел их положить.

2. **Определить локацию**
   Подпись локации видна клиентам на каждом фото и влияет на выбор ими локации для съёмки,
   поэтому ошибка здесь хуже, чем лишний вопрос.
   - Пользователь назвал локацию — бери её в написании с сайта: `Утёс`, `Эль-Гуна`,
     `Пустыня`, `Хургада (Мамша)`, `Море + Пустыня`.
   - Не назвал — открой новые фото (Read) и сравни с эталонными снимками локаций:
     `img/sofaga` — Утёс, `img/sofaga_sea` — Море + Пустыня, `img/el_gouna` — Эль-Гуна,
     `img/desert` — Пустыня, `img/mamsha` — Хургада (Мамша).
     Предложи вариант по каждой группе фото и дождись подтверждения пользователя.
   - Совсем новая локация (которой нет на сайте) — уточни у пользователя точное название
     и добавляй с флагом `--new-location`.

3. **Добавить** — один вызов на каждую пару «раздел + локация»:
   `python .claude/skills/add-photos/scripts/add_photos.py add couple "Утёс"`
   Если в разделе фото с разных локаций, передай файлы явно, группами:
   `python .claude/skills/add-photos/scripts/add_photos.py add single "Пустыня" photo_a.jpg photo_b.jpg`

   Скрипт:
   - переименует фото в следующие свободные номера (порядок по имени = по времени съёмки);
   - сделает WebP (до 2000px) и миниатюру `thumb/N.webp` только для этих фото —
     функциями из `optimize_images.py`;
   - вставит слайды **в начало** раздела в `index.html` — свежие работы посетитель видит первыми;
   - добавит фото в начало блока раздела в `sitemap.xml` и обновит `<lastmod>` —
     чтобы Google Картинки быстрее их проиндексировали.

   Скрипт остановится, если локация написана не так, как на сайте (например «Утес» вместо
   «Утёс») — исправь написание, а не добавляй `--new-location`.

4. **Проверить**: в выводе блок «Проверка HTML» без ошибок; `git diff --stat` показывает
   изменения только в `index.html` и `sitemap.xml` (плюс новые файлы в `img/`).

5. **Отчитаться**: что во что переименовано, вес до/после, в какой раздел и с какой
   локацией добавлено. Не коммить, пока пользователь не попросит.

## Пограничные случаи

- Поддерживаются `.jpg`, `.jpeg`, `.png` (регистр расширения не важен). HEIC/WebP/RAW скрипт
  не увидит — попроси пользователя экспортировать в JPG.
- Если нужно, чтобы фото шли в другом порядке, — переименуй их до запуска (например `a_…`, `b_…`).

## Ограничения владельца сайта

- Существующие фото не переименовывать, их alt не менять, существующие слайды не
  переставлять и не удалять — это решения владельца по SEO и оформлению.
- У новых фото alt в том же формате, что у соседних: «Парное фото N», «Семейное фото N»,
  «Индивидуальное фото N» (скрипт делает это сам).
